# FileBridge 设计说明

只记录**代码里看不出来**的取舍。协议字段、路由、表结构以源码为准（`protocol.py` /
`routes/` / `db.py`）；安装与运维见 **[部署手册](部署手册.md)**。

## 一、通道划分：控制走 WS，数据走 HTTP

判据是**大小 + 是否要续传**，不是"看情况"：

| 场景 | 通道 | 理由 |
|---|---|---|
| 指令、心跳、状态 | WS | 小消息、低延迟、需要 A 主动推 |
| 文件上传（>1MB） | HTTP 分片 | 可续传、可并发、失败可单块重传、不占用控制连接 |
| 极小文件（<64KB） | 预留 WS 内联 | v1 未实现；真要做必须先定上限，否则会堵住指令通道 |

大文件与心跳共用一条 socket 一定会互相阻塞：B 侧只要有一处同步文件 IO 写进协程，
心跳就发不出去，A 会误判它离线，上传被中断且现象诡异。所以 B 侧所有
`open/read/hash` 都走 `asyncio.to_thread`，数据通道从物理上分离。

## 二、状态只有一个持有者

任务状态、上传进度、文件行都只由 A 写。B 不维护镜像状态，也就没有"两边对不上"这类
问题——代价是 B 必须信任 A，这可以接受，因为 A 本来就是任务与文件的持有方。

块幂等是同一条思路的延伸：续传不需要额外的断点文件，A 告诉 B 哪几块已收，B 从第一个
缺口继续，重复上传只是多花一点流量。

## 三、存储为什么长这样

| 决定 | 不这么做会怎样 |
|---|---|
| 单个 `.part` 预分配 + 偏移写 | 每块一个文件，`complete` 时要拼装，磁盘峰值 **2×**（5GB 文件要 10GB） |
| 每块独立 `open/seek/write/close`，不用常驻 fd + `os.pwrite` | pwrite 要给每个进行中的上传维护长生命周期 fd，还得处理会话过期时的关闭与泄漏；1–8MB 配一次 open 的开销相对数据量可忽略。压测成瓶颈再局部替换，不影响协议 |
| 磁盘文件名用 `file_id`，原始名只进库 | 一并解决中文/emoji 名、重名覆盖、路径穿越、大小写文件系统冲突 |
| 两字符分片目录 | 单目录十万文件时列目录与 stat 明显变慢 |
| `os.replace()` 原子改名 | 保证"库里有的文件一定完整"，不会出现半截文件 |
| `received_json` 存已收块号 | v1 够用；单文件上万块再换 bitmap BLOB |

代价是 `complete` 时要顺序读一遍算 sha256（5GB 机械盘约 30 秒，SSD 10 秒内）。这个
代价买的是"哈希由服务端自己算"——信客户端报的哈希等于没校验。

## 四、协议：解析宽松，执行严格

`Message.command` 在线上是**裸字符串**，不是 `CommandName` 枚举。

这是踩出来的：声明成枚举后，老版本 B 收到一个它不认识的新命令，会在 **pydantic
校验阶段**就失败 → 整条连接被关掉；而正确行为是回一个 `unknown_command`，让 A 知道
"这台机器不会做这件事，别指望它"。

所以 `Message.parse` 接受任意 64 字符以内的命令名，`handlers.dispatch` 对照白名单
拒绝未列举的。封闭性保住了，同时协议向前兼容。

## 五、路径校验做两层，不是重复

- **A 侧**：C 提交的 `path` 先规范化（拒绝绝对路径、拒绝 `..`、按根目录拼接）再下发
- **B 侧**：拿到路径后独立 `resolve()` + 前缀包含判断

A 是唯一暴露面，可能被绕过；B 是真正持有文件的一方，必须自己兜底。**绝不能因为
"A 已经校验过了"就在 B 上省掉。**

关于分隔符：协议里固定 `/`（与平台无关），而 `is_within()` 比较的是已 resolve 的
**真实本地路径**，那里用 `os.sep`。这不是兼容分支——硬编码 `/` 会让这段判断的正确性
依赖"分隔符恰好相同"这个巧合。

## 六、Linux 是一等约束

入口 `require_linux()` 不是 Linux 直接 `exit 2`。挡的不是"跑不起来"，而是"看起来
能跑"：沙箱在非 POSIX 文件系统上的行为差异（保留设备名阻塞读线程、备用数据流、
尾随空格别名）没有一条被验证过，放它跑等于制造一个没人负责的运行态。

真实存在的约束：

| 约束 | 后果 | 处理 |
|---|---|---|
| 只有 `/` 是分隔符 | 反斜杠是**合法文件名字符**，按 `\` 切会把 `a\b` 误判成两级目录 | 协议层只按 `/` 切分，单测钉住 |
| 大小写敏感 | `Report.txt` 与 `report.txt` 是两个文件 | 不做任何大小写归一 |
| 软链接无需特权 | 根目录里一个指向 `/etc` 的链接就是完整逃逸 | `resolve()` 后判包含，不能只查"是不是链接" |
| 软链接环 / 悬空链接 | `resolve()` 抛 `RuntimeError` / `OSError` | 捕获转 `forbidden`，不冒泡成 500 |
| 文件可能在读的过程中被追加 | 日志文件是典型场景，读出的字节数 ≠ stat 时的大小 | 前后各 stat 一次，不一致返回 `size_changed` |
| POSIX 权限位 / ACL | 无读权限时 `open` 抛 `PermissionError` | 转 `forbidden`，错误信息带相对路径 |
| 单文件名 255 字节、路径 4096 | 超长触发 `ENAMETOOLONG` | 相对路径进沙箱前先做长度校验 |
| NFS / SMB 挂载 | `resolve()` 可能长时间阻塞，拖住事件循环 | 列目录与 stat 放线程池并设超时 |

读失败三种情形不要混为一谈：路径不存在 → `file_not_found`；权限不允许 → `forbidden`；
内容在变 → `size_changed`。最后一种最容易被忽略，也最不能容忍——半截文件不能当成
完整文件交上去。

## 七、B 的只读不变量

不靠"写代码时小心"，靠三层结构性保证：

1. 命令枚举里没有任何写操作——没有 `delete`、`rename`、`write`、`run_command`
2. agent 打开共享目录下的文件只用 `"rb"`，全代码库不出现 `"w"` / `"a"` / `"r+"`——
   有一条测试扫描源码强制这一点
3. 沙箱只提供 `resolve()` 和列目录，没有写入入口

B 唯一会写的是它自己的日志文件。"只读"指共享目录，不是"整个进程不落盘"。

## 八、踩过的坑

| 问题 | 教训 |
|---|---|
| `Path.relative_to()` 把根目录算成 `"."` | 根目录出现两种表示。不要反算，直接拼相对路径 |
| `lifespan` 读的是模块级 `settings` 单例 | 测试注入的临时目录不生效，会往仓库里建 `storage/`。一律读 `app.state` |
| `is_within()` 硬编码 `/` 做包含判断 | 内部比较必须用 `os.sep` |
| `/api/v1/files`、`/tasks`、`/agents` 忘挂会话依赖 | 单元测试全绿，未登录就能读文件列表。是端到端"匿名必须 401"抓出来的——**安全属性只能用"从外面打进去"的方式测** |
| `Message.command` 声明成枚举 | 见第四节：解析阶段就炸并关连接 |
| agent 的 `__version__` 没定义 | hello 帧要读它 → 第一帧抛异常 → 表现为"一直重连、A 侧永远离线"。握手路径上的模块级变量都要有测试 |
| 密码搬进数据库后，登录接口仍读环境变量 | "密码明明设好了却返回 503"。改了配置来源，就要把所有"读配置做判断"的地方找一遍 |

## 九、测试只测三个会出事的点

不追求覆盖率数字。

1. **沙箱逃逸矩阵**——`../`、`..%2f`、软链接、绝对路径、超长/超深路径、空字节、
   反斜杠当普通字符。每例断言被拒绝，且错误码是 `forbidden` 而不是 `internal`
2. **协议 round-trip + 契约**——每个消息类型序列化再反序列化必须等值，未知 `v` 必须
   被拒；两端 `protocol.py` 逐字节相同、都通过同一份黄金样例。没有独立协议包时，
   这两条是唯一的漂移防线
3. **端到端续传**——真的起 uvicorn、真的跑 agent、真的分片上传（含中文文件名），
   中途断开再重连，校验最终 sha256

另加一组并发指令测试：同时 5 个请求，用消息 `id` 不串来验证没有帧交错。

软链接用例有环境依赖：某些文件系统上 `symlink_to()` 不报错却没真建链接
（`islink()` 返回 False），这种环境必须显式探测并 skip，否则是"测了但什么都没验证"
的假阳性。安全判断本身抽成 `is_within()` 独立单测，不依赖能否建链接——那条判断才是
真正挡住越界的东西。
